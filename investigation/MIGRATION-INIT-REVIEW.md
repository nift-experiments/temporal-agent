# Final migration-init review

The preserved Nift 4.9.0 guidance explicitly covers authored/rendered/hybrid source models, retained framework islands, complete publication boundaries, baseline freezing, profile/optimize/revalidate/benchmark, per-process versus aggregate RSS, and fresh-checkout verification. Those are strengths demonstrated during this campaign. Public clean clones and T9 complete-publication measurements now pass. It did not require replacing the generated workflow with an older experiment playbook. Nift core and generated templates remain unchanged.

Concrete additions for later Nift planning:

1. **MIGRATION.md, architecture proof:** “For syntax-rich HTML, prove raw composition and explicit dependencies before scaling. The composition path must preserve literal template-like syntax inside examples. Record the complete normal command that prepares transient products and calls Nift; bare composition is not a substitute for that pipeline.” Add a small raw HTML/dependency example as optional generated scaffolding.
2. **MIGRATION.md, source model:** “A rendered-source model owns initial island markup and secondary views as well as HTML. Define maintenance of downloads, LLM text, navigation, metadata and indices. Two forced copies of maintained HTML can agree while a companion view is stale; verify semantic consistency with the intended edit.” This should be a source-ownership table, not an instruction to make authored and rendered projects identical.
3. **MIGRATION.md, islands:** “Test hydration after component, props, CSS-module and metadata changes. Keep server/client context and stylesheet identifiers consistent; coordinate shared state across independent roots. Use an explicit markup refresh when rendered HTML is maintained. If a page genuinely depends on request/browser state, document whether client mounting replaces static markup.” Include immutable JS/CSS asset naming in the checklist.
4. **investigation/EXTERNAL-INPUTS.md:** Add asset ownership, maintained location, normal-build behavior and explicit-refresh command fields. Proposed wording: “Generated upstream assets may become maintained migration assets. Keep their bytes and publish them normally; disclose the ownership difference and measure explicit updates separately. Application-cold cache deletion must not delete maintained assets.”
5. **MIGRATION.md, browser parity:** “Before first navigation, fulfill or block remote transports deterministically. Do not send feedback, telemetry, analytics, search uploads or private calls. Separate local UI/transport evidence from backend functionality not exercised.” Credential inventory alone is not the same as safe browser transport defaults.
6. **MIGRATION.md, incremental correctness:** Add source include, structured reference, metadata, route add/rename/delete, and island changes. Check canonical/OG/download/LLM/navigation effects, retire owned products, and verify missing/corrupted transient cache products repair correctly. Force recomputation must bypass the caches under test.
7. **MIGRATION.md, benchmark definitions:** Add a per-scenario cache-state table covering renderer, bundles, Nift metadata, publication outputs, search, OG and installed dependencies. Keep maintained assets distinct from caches. Require stage costs plus command wall time and explain startup/unattributed cost. Production publication and development/HMR remain separate.
8. **HANDOVER.md, final gate:** “Reproduce from public clean clones without proof-stage node_modules links, hidden baseline paths or temporary CSS/module-resolution assumptions. Record the normal command and exact tested revision.” Propose optional `investigation/ARCHITECTURE.md` and source-to-product dependency inventory scaffolding.

9. **MIGRATION.md, external-input verification:** “A successful build exit is insufficient when fetch/sync steps can fall back to placeholder content. Verify the external revision and publication-family inventories after acquisition; retain and reject wrong-corpus attempts.” Temporal’s observed HTTP/2 cookbook failure triggered a successful placeholder build during T9, so this is a concrete verification lesson.

These are proposed wording/scaffolding improvements for future core work. They do not reopen this migration or authorize Nift changes.
