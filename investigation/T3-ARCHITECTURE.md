# T3 representative architecture

Seven real published routes cover CLI tabs/code/downloads, authored SDK MDX with synchronized language groups and annotated code, generated CLI reference, Python SDK content, included AWS regions and Mermaid, retained retry simulation, and the Cloud SLO accordion. This is a bounded proof, not whole-site parity or benchmark acceptance.

Authored: maintained Markdown/MDX and frontmatter → standalone official MDX compiler plus actual Temporal components → transient rendered HTML → Nift raw composition → publication. Rendered: maintained HTML, explicit metadata and pre-derived Markdown downloads → Nift raw composition → publication. No Markdown renderer executes in routine rendered-project builds.

React islands retain code controls, annotated code, Mermaid/zoom, retry simulation, page Markdown actions, search, mobile TOC and JSON tables. Native controllers handle shell navigation, themes, synchronized tabs and details. Framework contexts support these components without mounting the Docusaurus page application or generated route graph. CSS class hashing uses canonical source paths so authored and rendered repositories can share unchanged upstream styling.

Nift raw file reads preserve literal template-like examples. Explicit dependencies include maintained page input and transient prefix/body/suffix files. The five mutation checks cover body, authored include and route-shell updates; each incremental file manifest must equal a forced publication after deleting only the derived publication tree, with source restoration in finally.

Accepted OG image bytes are maintained under static/img/og and copied; no routine OG generation. Static ownership is explicit even though this prototype uses a maintained source tree and derived publication tree. Remote browser services are intercepted and deterministic. Algolia index/backend, Kapa backend and feedback delivery are not exercised.

Temporary development node_modules links point at the pinned baseline installation. Fresh-clone dependency installation remains a required final gate. No benchmark claims use these seven-route timings. Per-route shells are an initial compatibility proof; shared shell/navigation models, metadata lifecycle, route retirement, complete projections and corpus-wide island coverage belong to subsequent checkpoints.

Run with Node 24: node tools/publish.cjs; force: node tools/publish.cjs --force. Browser fixture tooling under evidence requires the preserved sibling temporal-baseline. Final portable verification remains pending.
